# Invited Table Assignments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Allow an unconfirmed Admin Invite to be assigned, moved, and removed in Tables and MAP while preserving its table when it later becomes a confirmed RSVP.

**Architecture:** Extend `staff_table_assignments` so exactly one RSVP or invite owns each row. Build canonical table groups in a pure shared helper, use typed assignment subjects in the API/UI, and atomically promote or remove invite assignments with a PostgreSQL RSVP trigger.

**Tech Stack:** Cloudflare Pages Functions ES modules, vanilla JavaScript, Supabase Postgres/PostgREST, Node `node:test`.

- [ ] **Step 2: Run the focused test and confirm failure**

Expected: FAIL because the migration does not exist.

- [ ] **Step 3: Implement the additive migration**

Use idempotent `ALTER TABLE` and `DO $$` constraint guards. The final assignment shape is:

```sql
id bigint generated by default as identity primary key,
event_key text not null,
rsvp_id bigint references public.rsvps(id) on delete cascade,
invite_id text references public.guest_list(id) on delete cascade,
table_id text not null references public.staff_tables(id) on delete cascade,
assigned_at timestamptz not null default now(),
constraint staff_table_assignments_one_subject check (num_nonnulls(rsvp_id, invite_id) = 1),
unique (event_key, rsvp_id),
unique (event_key, invite_id)
```

Add `sync_invite_table_assignment_to_rsvp()` as an `AFTER INSERT OR UPDATE OF status, guest_id` trigger. For `attending`, preserve the invite's `table_id` while moving ownership to `NEW.id`; if an RSVP assignment already exists, delete the obsolete invite row. For `declined`, remove the invite assignment.
